# personal-data-denylist.txt -- patterns that must never enter this PUBLIC repo.
#
# One POSIX ERE per line. Blank lines and #-comments ignored. Matching is
# case-INSENSITIVE: the first inventory of this repo (2026-08-30) was run
# case-SENSITIVELY and found 21 files; the same grep with -i found 44, because
# `Dillon` capitalised is the dominant form. A case-sensitive denylist is a
# denylist with half its teeth.
#
# SCOPE, and it is the whole design: this gate reads ADDED LINES IN A DIFF, not
# the working tree. The repo's history and current HEAD legitimately contain
# author provenance (Dillon nodded 2026-08-30: authorship stays, history stays),
# so a whole-tree scan would fail on day one and be disabled within a week. A
# gate that must be switched off is not a gate.
#
# THEREFORE these patterns target the LEAK classes only -- machine identity and
# operator secrets -- never the AUTHOR class. "Dillon", "Dillon's", provenance
# citations and the LICENSE author line are DELIBERATELY ABSENT from this file.

# --- tailnet addresses -------------------------------------------------------
# Tailscale hands out the whole CGNAT block 100.64.0.0/10. Two earlier drafts of
# this pattern (100\.1[0-9]{2}\. and 100\.10[0-9]\.) BOTH missed the one real
# address in the repo, modules/confirm-pkg.nix relayAddr = "100.71.238.38".
# That literal is the armed bad commit in the battery for exactly this reason:
# it is the string that already defeated two instruments.
100\.(6[4-9]|[7-9][0-9]|1[01][0-9]|12[0-7])\.[0-9]{1,3}\.[0-9]{1,3}

# --- operator home paths (the mesh bus) --------------------------------------
jarvis-sync

# --- mesh brain wiring: process names and bot handles -------------------------
run_rabbot
HeraldTalbot

# --- operator account ---------------------------------------------------------
dtd@

# --- Telegram numeric ids ------------------------------------------------------
# Long bare integers next to a telegram/chat/user-id key. Deliberately narrow:
# a blanket \b[0-9]{9,12}\b matches nix hashes, timestamps and flake.lock.
(telegram|chat|user)[_-]?id[^0-9\n]{0,20}[0-9]{7,15}

# --- 2026-08-30 widening -----------------------------------------------------
# WHY THIS BLOCK EXISTS. Rabbot flagged `root@192.168.1.253` sitting in
# docs/log-console-spec.md at HEAD and framed it as "the diff-gate won't catch
# it" -- true, the gate scans diffs. But testing the claim with a control arm
# (the known-bad tailnet literal on the same code path, which returns 1) showed
# the gate returned 0 for that line IN A DIFF TOO. The defect was never the
# diff/HEAD distinction; it was that this list had no LAN-address rule at all.
# A gate is only as good as its patterns, and "it scans the right thing" says
# nothing about whether it recognises what it sees.
#
# RFC1918 private ranges. These are the operator's LAN, which is personal
# infrastructure data exactly like the tailnet block above. Range DEFINITIONS
# (a firewall rule saying 10.0.0.0/8) are legitimate and take `# gate-allow`;
# a specific host address never is.
192\.168\.[0-9]{1,3}\.[0-9]{1,3}
10\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}
172\.(1[6-9]|2[0-9]|3[01])\.[0-9]{1,3}\.[0-9]{1,3}

# mDNS hostnames leak both the machine names and the household (Fable P2).
[A-Za-z0-9-]+\.local\b

# Personal mail domains -- an author line is fine (Dillon's ruling), a mailbox
# is not.
@(gmail|proton|protonmail|icloud|outlook|hotmail)\.
# Tailscale auth keys and Telegram bot tokens: live credentials, not identifiers.
tskey-auth-[A-Za-z0-9-]{6,}
[0-9]{8,10}:[A-Za-z0-9_-]{35}
