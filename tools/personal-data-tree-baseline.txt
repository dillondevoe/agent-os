# personal-data-tree-baseline.txt -- the hits in HEAD that `personal-data-gate.sh --tree`
# accepts. One "<path><TAB><pattern>" pair per line; the pattern must match a line in
# tools/personal-data-denylist.txt EXACTLY.
#
# WHY PER-PATTERN AND NOT PER-FILE. A file-level allowlist retires the file from scrutiny, so
# the next leak into an already-listed file lands silently -- the allowlist becomes the hole.
# Scoped this way, a synthetic 192.168.1.1 in a VM test is accepted and a tailnet auth key
# appearing in that same file tomorrow is still BLOCKED.
#
# WHAT IS IN HERE. Only two classes, and neither is operator identity:
#   1. RFC1918 / CGNAT *range literals* (10.0.0.0/8 and friends) in firewall and threat-model
#      text. These are range DEFINITIONS, not addresses of anything.
#   2. Synthetic fixture addresses in VM tests -- .1 gateways, 10.0.2.15 (QEMU's standard guest
#      address), 169.254.169.254 (the cloud metadata endpoint every SSRF test uses). None of
#      them is a host on the author's network; the real one appears nowhere in this repo.
#
# Adding a line here is a claim that a human looked. Do not add one to make a build green.
